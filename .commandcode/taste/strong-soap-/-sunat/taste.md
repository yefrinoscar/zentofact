# strong-soap / SUNAT
- When passing a downloaded/inlined WSDL string to `soap.createClient()`, write it to a temp file first and pass the file path. `createClient()` treats its first argument as a URL or file path — passing raw WSDL XML content directly will be mistaken for a massive filename, causing `ENAMETOOLONG`. The `fetchWsdl()` approach should download+inline into a temp `.wsdl` file, then pass that path to `createClient()`. Confidence: 0.70
- For SUNAT WSDL authentication with strong-soap, use `wsdl_options: { auth: { user: '...', pass: '...', sendImmediately: true } }` as an object, NOT the string format `'user:pass'`. The `@cypress/request` module used by strong-soap only handles the object format (it checks `options.auth.user`/`options.auth.pass` properties), while the standard `request` module supports both formats. The `sendImmediately: true` sends Basic auth on the first request without waiting for a 401 challenge. Confidence: 0.80
- When passing a downloaded WSDL as a local file to strong-soap, convert relative `<wsdl:import>` locations to absolute URLs first. Otherwise `url.resolve(localTempPath, relativeImport)` resolves to a local file path (e.g., `/tmp/billService?ns1.wsdl`) causing `ENOENT`. Use `new URL(relativeLocation, wsdlUrl).href` to absolutize. Confidence: 0.70
- Process boletas one-by-one (sequentially), not in batch/all at once. Stop on first failure — do not continue to the next boleta if the current one fails. Confidence: 0.85
- When debugging SUNAT integration issues, check the reference PHP project (Greenter library / solo://proj/5) to understand how authentication, WSDL handling, and SOAP calls are structured before attempting fixes. Confidence: 0.75
- Send only one summary per sendSummary call regardless of how many boletas are included. Confidence: 0.85
- When SUNAT returns multiple ticket IDs for a single summary, consolidate them into one and query status per ticket, grouping results under the summary. Confidence: 0.75
