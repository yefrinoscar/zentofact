# Reconcile with SUNAT before reissuing a document number

A failed send to SUNAT does not tell us whether SUNAT registered the document. Treating every error as a rejection reissued documents with new numbers while SUNAT had already accepted the original, and treating an error as "number is free" collided with documents of another issuer using the same series. ZentoFact therefore classifies every send: only a CDR with code 0 or 4000+ is acceptance, only a CDR with code 2000-3999 burns the number, and everything else (timeouts, `1033`, `0130`, missing CDR) is `NO_CONFIRMADO`. A `NO_CONFIRMADO` document is reconciled with `getStatusCdr` before anything else happens: accepted and matching our customer or XML hash → `ACEPTADO`; accepted for someone else, voided, or after three resends of the same XML → `REVISION_MANUAL`; explicit "does not exist" (`0011`) → resend the same signed bytes; rejected → a new number, at most twice per order. A failed query never counts as "does not exist".

Each number has exactly one signed XML, stored before sending and recorded in `sunat_document_xml`; every send, status check and block is appended to `sunat_emission_attempts`. Both tables reject `UPDATE` and `DELETE`. An order has at most one active sales document, enforced with an advisory lock per order instead of a partial unique index, because a document voided by an accepted credit note keeps its `ACEPTADO` state and the order may legitimately receive a new one. Credit notes keep the one-note-per-document constraint: an unconfirmed note is kept and reconciled, and only a note rejected with a CDR is discarded, with its evidence left in the attempts history.

A sweep every 15 minutes moves `ENVIANDO` documents older than 10 minutes to `NO_CONFIRMADO`, requeues failed jobs so they reconcile and upload to Falabella, and emails once about documents still unaccepted two days after issue. Every 6 hours it queries the next two numbers of each series in use (all companies keep `B001` for boletas and `F001` for facturas); if SUNAT already has one of them, another system is issuing with that series and an alert is emailed. Emission is not paused: any document that collides is caught by reconciliation and moved to `REVISION_MANUAL` instead of being duplicated.
